# darkraise-web-template

pnpm monorepo for the `darkraise-ui` React 19 kit and its scaffolder.

| Path            | Package                  | What it is                                           |
| --------------- | ------------------------ | ---------------------------------------------------- |
| `packages/ui`   | `darkraise-ui`           | the kit: components, hooks, theme, layouts, forms    |
| `apps/template` | `darkraise-web-template` | demo app, component showcase and Playwright test bed |
| `create-app`    | `create-darkraise-ui`    | `npm create darkraise-ui` CLI (`bin/create.mjs`)     |

The two published packages share one version line. `packages/ui/CHANGELOG.md`
has an `[Unreleased]` section that the Release workflow closes; the unreleased
work is 7.0.0, and `docs/upgrade-7.0.md` is its migration guide.

## Commands

```bash
pnpm install
pnpm build                    # kit -> packages/ui/dist
pnpm dev                      # kit watch build
pnpm dev:template             # build the kit, then the demo app on :5176
pnpm -r typecheck && pnpm lint && pnpm exec prettier --check .
pnpm test                     # Vitest in the kit and the demo app
pnpm --filter darkraise-ui exec vitest run src/theme   # one area
```

The browser suite and its rules are in `apps/template/e2e/README.md`.

## Things that bite

- **The demo app consumes `packages/ui/dist`, not source.** Rebuild the kit
  (`pnpm --filter darkraise-ui build`) before running the demo or e2e on kit
  changes, or you test old code. The watch build skips `.d.ts`; run
  `pnpm --filter darkraise-ui run build:types` after changing an exported type.
- **Playwright reuses any server on its port** (5176 by default, also held by
  `scripts/dev.sh` and `deploy/compose.yaml`, which can serve stale kit CSS).
  For a full run, pick a free port so Playwright starts a fresh server:
  `E2E_PORT=5190 E2E_WARM=1 TMPDIR=/root/.cache/pw-tmp pnpm --filter darkraise-web-template exec playwright test`.
  Keep `TMPDIR` on disk; a full `/tmp` tmpfs crashes Chromium on every page.
  Kill the servers you start by PID.
- **Generated files.** `theme.css` imports every component stylesheet between
  `AUTOGENERATED COMPONENT IMPORTS` markers (`generate:imports`; the
  pre-commit hook reruns it for staged component CSS).
  `create-app/bin/axes.json` comes from the kit's axis registry
  (`pnpm --filter darkraise-ui write:scaffold-axes`); a kit test fails when it
  drifts. `apps/template/src/routeTree.gen.ts` is gitignored TanStack Router
  output (`pnpm --filter darkraise-web-template generate:routes`).
- `scripts/init.mjs` initialises a project that copied it into its own
  `scripts/` folder, writing `src/` and `vite.config.ts` one level up. It
  exits when that directory holds `pnpm-workspace.yaml`, so it never
  overwrites this repository.
- CI runs only five Playwright specs. Changes under `packages/` or `apps/`
  need the full suite locally before merge, and changes under
  `packages/ui/src` or `apps/template/src` also need the visual baseline
  (`BASELINE=1 ... playwright test 18-baseline --workers=1`).

## Kit conventions

- Read `packages/ui/CONTRIBUTING.md` before touching a component: co-located
  `<kebab>.css` under `@layer components`, `dr-` classes, variants and state as
  `data-*` attributes, no `!important`, no Radix.
- Inside `packages/ui/src`, import through the tsconfig aliases (`@lib/*`,
  `@theme/*`, `@layout/*`, `@primitives/*`, ...).
- The stylesheet contracts (removed tokens and axes, focus rings, radii,
  touch targets, contrast) are scan tests in `packages/ui/src/styles/*.test.ts`;
  run them after any CSS change.
- User-facing kit changes get a line under `[Unreleased]` in the CHANGELOG.
  Breaking ones also get a row in `docs/upgrade-7.0.md`.
- Docs that describe the kit: root `README.md` (overview, CLI),
  `packages/ui/README.md` (consumer usage, shipped to npm),
  `docs/custom-styles.md` (style, preset and font definitions). Update the
  one whose claim a change breaks.

## Commits

Conventional commits enforced by commitlint (`fix(ui): ...`, `docs(repo): ...`).
Hooks: pre-commit runs lint-staged (ESLint, Prettier), pre-push runs
`pnpm -r typecheck`. A `feat` commit to `packages/ui` or `create-app` on
`master` makes the next release a minor, anything else a patch; a breaking
marker fails the release run, so a major ships by pushing a `vX.Y.Z` tag.

`docs/specs/` holds committed design specs. `docs/superpowers/` is gitignored
local working state (plans, registers, `gates.md` with the full merge gates).
