# UI proof: closing overlays let presses through, and no-op changes stay silent

**Contract:** touch
**Fingerprint:** bf1041605b580231
**Judge:** ship bf1041605b580231 — docs/dforge/ui-ux/proofs/2026-11-11-closing-clicks.judge.md
**Platform:** web
**Viewports:** 375x812, 1280x800
**Themes:** light, dark
**Evidence:** local

## Delta

**UI/UX depth:** touch — every exit-animated overlay surface (content and modal backdrops) takes no pointer events while `data-state="closed"`, and `useControllableState` no longer calls a change callback with the value the component already has. No visual change.

- **UX-1** — During a popover's exit, a second press where its Done button was does not run Done's handler again.
- **UX-2** — During a modal dialog's exit, a press on the page behind its fading backdrop reaches the page; the dialog content and the backdrop both compute `pointer-events: none` while closed.
- **UX-3** — An open dialog's backdrop still covers the page: a press on it does not reach the control behind it.
- **UX-4** — Escape on an open popover calls `onOpenChange(false)` once and returns focus to the trigger; a second Escape during the exit adds no call.
- **UX-5** — Change callbacks fire only for real changes: setting the current value calls no `onChange`; two sets in one tick both apply; a setter kept from an earlier render compares against the latest value (submenus close their sibling); a controlled owner that kept its value is asked again on a later set. Every exit-animated surface in the kit's stylesheets carries the closed-state rule.
- **OP-1** — Proven at 375x812 and 1280x800, light and dark, with no accessibility violations in the open dialog, no console errors and no horizontal overflow.
