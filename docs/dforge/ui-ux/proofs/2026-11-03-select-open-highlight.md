# UI proof: Select opens on its selected option

**Contract:** touch
**Platform:** web
**Viewports:** 375x812, 1280x800
**Themes:** light, dark
**Evidence:** local
**Fingerprint:** b5c5a398b03f33e4
**Judge:** ship b5c5a398b03f33e4 — docs/dforge/ui-ux/proofs/2026-11-03-select-open-highlight.judge.md

## Delta

**UI/UX depth:** touch — opening a `Select` highlights the option matching its value, so arrow keys move from the current value

- **UX-1** — With a value, Enter on the focused trigger opens the list with the selected option highlighted and focused; ArrowDown then highlights the next option.
- **UX-2** — With a value, ArrowUp on the trigger also opens on the selected option; ArrowUp then highlights the previous option.
- **UX-3** — With a value, a pointer open highlights and focuses the selected option.
- **UX-4** — With no value, a pointer open highlights nothing and focuses the list; Enter starts at the first option and ArrowUp at the last, including under React StrictMode.
- **UX-5** — Enter commits the highlighted option, closes the list and returns focus to the trigger.
- **UI-1** — Worst case: in a 50-option list whose value is the last option, a keyboard open shows the selected row fully inside the list, and the page does not scroll.
- **OP-1** — Proven at 375x812 and 1280x800, light and dark, with no accessibility violations in the open list, no console errors and no horizontal overflow.
